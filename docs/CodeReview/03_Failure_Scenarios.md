# Summit Events Custom Layer - Failure Scenarios

This document maps important production failure scenarios to current handling, likely gap, impact, and mitigation.

| Scenario | Current handling | Gap | Business impact | Recommended mitigation | Priority |
|---|---|---|---|---|---|
| Event has no Account | Wizard/docs recognize Account as important; readiness logic checks some Event fields. | Enforcement is not consistent across direct edits, imports, and flows. | Campaign, reporting, and downstream business ownership can be wrong. | Add Account to shared readiness policy and admin reports. | High |
| Event is paid but missing Payment Gateway | Wizard loads payment gateway options and can save payment fields. | Need consistent server-side blocker for paid/public launch, not just UI guidance. | Broken payment registration or failed checkout. | Block publish/readiness when paid event lacks gateway. Add test. | Critical |
| Event is paid but missing Accounting Department | Wizard exposes accounting department options. | Same as payment gateway: must be enforced in policy. | Incorrect accounting routing or payment reconciliation failure. | Require Accounting Department for paid events in readiness policy. | Critical |
| Event has payment settings cloned unintentionally | Clone surfaces exist, but sensitive setting review is not yet strong enough. | Users may copy old gateway/accounting/Opportunity/email settings. | Wrong payment destination, wrong Opp creation, or wrong emails. | Add clone review/reset step for payment, Opportunities, confirmations, reminders, and location. | High |
| Event has no Instance | Readiness/service logic can count instances; wizard can create first instance except preview. | Direct Event creation or old flows can leave Event without an Instance. | Public registration cannot happen or users cannot find event dates. | Treat "no active instance" as readiness blocker; add dashboard action to create first instance. | High |
| Instance has no start date/time | Wizard and readiness consider dates. | Need consistent validation for all save paths and imports. | Event appears without schedule or sorts incorrectly. | Require date/time in readiness policy and data import checklist. | High |
| Instance has conflicting location settings | Wizard has location type logic. | Readiness currently requires physical fields regardless of virtual/online type. | Online events can be marked Not Ready; physical events may lack right fields. | Branch by location type and test onsite/offsite/virtual. | High |
| Virtual event missing meeting link | Some virtual fields are handled in wizard. | Readiness policy should explicitly block virtual launch without link or joining instructions. | Attendees cannot join. | Add virtual-specific readiness checks. | High |
| Physical event missing address/map/parking | Wizard validates some fields for onsite/off-campus. | Direct edits/imports can bypass; readiness should be authoritative. | Attendees arrive at wrong/no location. | Add physical-specific readiness checks and admin report. | High |
| Registration exists without Contact or Email | Registration browser flags missing contact and selects email/contact fields when present. | Missing email without contact is not clearly a blocker in all workflows. | Reminder/email delivery can fail. | Add data health check for registrations with no contact and no usable email. | High |
| Registration cancelled after reminder fields set | Reminder logic was not fully present in source. | Pardot/Account Engagement may consume stale reminder fields. | Cancelled attendees may receive reminders. | Revisit reminder field update automation; clear/suppress reminder fields on cancellation. | High |
| Registration changes from one Instance to another | Mass update aligns Event to selected Instance when Instance is chosen. | Event-only update still allowed with warning. | Registration can point to Event and Instance that do not match. | Remove or admin-gate Event-only update; derive Event from Instance. | High |
| Duplicate registrations | Not fully visible in custom layer. | No custom duplicate prevention seen in reviewed source. | Capacity, attendance, and communications can be inflated. | Add duplicate detection by Event/Instance + Contact/Email, or report duplicates if managed package owns prevention. | Medium |
| Contact has multiple upcoming registrations | Registration browser can search and browse. | No special UX to show contact-level upcoming conflicts. | Staff may miss duplicate or conflicting attendance. | Add contact summary panel or duplicate/conflict report. | Medium |
| Reminder scheduled in the past | Reminder implementation not fully reviewed in source. | Needs explicit policy. | Reminders may fire immediately, not at all, or be stale. | Add validation and batch safety checks for reminder dates. | Medium |
| Reminder job runs late | Not fully visible in source. | Need monitoring and idempotent sent status. | Attendees receive late reminders. | Log scheduled/run/sent times and expose exception report. | Medium |
| Reminder job runs twice | Not fully visible in source. | Need idempotency by reminder key. | Duplicate reminders. | Use idempotent keys and sent status locks. | High |
| Reminder status fails to update to Sent | Not fully visible in source. | Need partial failure reporting. | Repeated sends or stale reporting. | Add error object/log and retry policy. | High |
| Batch partially fails | Some queueable readiness jobs exist; broader batch behavior not fully visible. | Need observability and retry. | Silent stale readiness or incomplete updates. | Add logging and scheduled reconciliation. | Medium |
| User lacks field permissions expected by LWC | Permission set grants key class access and some custom fields, but FLS strategy is inconsistent. | Services may fail or expose system-mode fields unexpectedly. | Confusing runtime errors or overexposure. | Add `stripInaccessible`/user-mode reads and permission tests. | High |
| User lacks related record access | Services run `with sharing`, so missing related access can hide rows. | Some methods may return generic errors or empty data without explanation. | Users think data is missing. | Return structured "no access/not found" messages and scope selectors. | Medium |
| Record type missing or renamed | Access service uses available record types, which is good. | Flows and older logic still use developer names/hardcoded names in places. | Broken filters/campaign automation after metadata changes. | Centralize record type mapping and add deployment checks. | High |
| Sandbox/production metadata differences | Docs clearly say Partial UAT is the build org. | Hardcoded URLs/names and source-only assumptions can differ. | Deployment/runtime differences. | Use custom metadata/labels and validate org dependencies before prod. | High |
| Large registration volume | Registration browser uses StandardSetController; roster export capped. | Not true infinite scale. | Slow/miscounted lists and incomplete exports. | Keyset pagination and async/chunked exports. | High |
| Daylight savings/timezone edge cases | Draft flow contains manual time formulas; Apex date/time handling needs targeted tests. | Tests for DST were not identified. | Wrong event times around DST. | Add tests for spring/fall DST and user timezone conversion. | Medium |
| Null or malformed location/meeting data | Wizard validates some fields. | Server-side policy should validate malformed URLs and inconsistent type combinations. | Public page confusion or broken links. | Add URL validation and type-specific rules. | Medium |
| Pardot/MCAE consumes stale reminder fields | Docs call out reminder-field sensitivity. | Custom layer does not show a full freshness mechanism. | Wrong audience receives reminders. | Recalculate/clear reminder fields on registration status/date changes. | High |
| Cloned event retains old location/reminder/payment settings | Clone and draft flow can carry old values. | Business review/reset step is missing or incomplete. | Bad event configuration spreads. | Clone governance screen with reset defaults and required confirmation. | High |
| Public image remains private in rich text | Public file service and LWC conversion exist. | Browser conversion can still fail; file lifecycle governance needs hardening. | Images fail on public registration page. | Server-side conversion or clearer one-click repair; allowlist image formats. | Medium |
| Preview record abandoned | Preview fields and inline cleanup exist. | No scheduled cleanup job. | Reporting pollution and possible Campaign side effects. | Scheduled cleanup and preview monitor report. | High |
