# Phase 0 - Business Decisions

Phase 0 item count: 13

These decisions should be confirmed before implementation begins or before the related feature is finalized. Recommended defaults are based on the review documents.

| Decision ID | Business question | Why it matters | Recommended default | Risk if undecided | Stakeholder owner | Technical dependency |
|---|---|---|---|---|---|---|
| BD-001 | Which fields are required before an Event is considered ready for public registration? | Readiness affects public pages, reminders, payment, and staff trust in dashboards. | Require Account, capacity, active Instance, date/time, location/virtual details, program scope, and paid-event payment fields when applicable. | Developers may implement inconsistent blockers across screens. | Event operations owner | BL-001 |
| BD-002 | Should missing Capacity always block readiness and launch? | Capacity controls overbooking and was called out as a documented showstopper. | Yes, capacity must be greater than zero. | Events can launch without capacity control. | Event operations owner | BL-001, BL-002 |
| BD-003 | Should paid events require both Payment Gateway and Accounting Department? | Payment routing and reconciliation depend on both fields. | Yes, both should be blockers for paid events. | Broken checkout or incorrect accounting. | Finance/accounting owner | BL-001 |
| BD-004 | Which location fields are required by location type? | Physical and virtual events need different readiness rules. | Physical/offsite require title/address/map/building/parking; online/virtual require meeting link/instructions. | Virtual events may be blocked incorrectly, or physical events may lack attendee instructions. | Event operations owner | BL-002 |
| BD-005 | Which sensitive fields must be reviewed when cloning? | Clone is useful but can carry stale payment, reminder, location, and Opportunity settings. | Require review/reset for payment gateway, accounting department, Opportunity creation, confirmation email, reminders, capacity, location, parking, and public images. | Old settings propagate to new events. | Event operations + finance | BL-025 |
| BD-006 | Should standard users be allowed to update Registration Event without Instance? | Event-only update can create Event/Instance mismatches. | No for standard users; derive Event from selected Instance. | Registration data integrity issues. | Event operations owner | BL-009 |
| BD-007 | Who may create public file links? | Public ContentDistribution links expose files outside authenticated Salesforce. | Limit to FIU Events power users/admins with custom permission. | Sensitive or unsupported files can be exposed. | Security/admin owner | BL-006 |
| BD-008 | Which public image file formats are allowed? | Some formats are safer and easier to render publicly. | Allow PNG, JPG/JPEG, GIF, WEBP; block SVG unless separately approved and sanitized. | Risky or unsupported assets appear in public pages. | Security/web owner | BL-006 |
| BD-009 | How long should preview records live? | Abandoned previews pollute data and automation. | 24 to 72 hours, with scheduled cleanup. | Preview records remain indefinitely. | Event operations owner | BL-007 |
| BD-010 | What should happen to reminder data when registrations are cancelled or moved? | Pardot/Account Engagement may consume stale reminder fields. | Cancelled/moved registrations should clear or suppress stale reminder fields. | Wrong attendees receive reminders. | Marketing automation owner | BL-010 |
| BD-011 | What should Account Engagement/Pardot treat as the source of truth for reminder eligibility? | Reminder data ownership needs to be explicit. | Salesforce registration status + current Instance/date should determine eligibility. | MCAE consumes stale fields. | Marketing automation owner | BL-010 |
| BD-012 | How should Event vs. Instance be explained in the UX? | Users think of "event" as one thing, but Summit separates parent Event and child Instance. | Use explicit labels: Event = program/configuration, Instance = date/session. Hide unnecessary selectors when user has one record type. | Users make changes in the wrong place. | Event operations owner | BL-001, BL-025, BL-028 |
| BD-013 | What export, public-file, and admin permissions should be separated? | Least privilege protects public data and financial setup. | Separate normal app use, public file creation, export, admin/readiness override, and campaign/admin cleanup permissions. | Permission set becomes too broad. | Salesforce admin/security owner | BL-008, BL-012, BL-023 |
